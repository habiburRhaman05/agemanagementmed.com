বুঝেছি এখন — আসল সমস্যাটা হলো **"common component ব্যবহার করলে per-section CSS override করা যাচ্ছে না"**, আর **"icon/card/slider সেকশন সব পেজে নেই, তাই generic component সেটা handle করতে পারছে না"**। এই দুটোর সমাধান একসাথে দিচ্ছি।

## সমস্যা ১: একই CSS সেকশন আর ইমেজ দুটোতেই লেগে যাচ্ছে

এইটা হয় কারণ একই class name বা একই root element একাধিক জিনিসের জন্য ব্যবহার করা হচ্ছে। সমাধান হলো — **প্রতিটা element এর জন্য আলাদা override slot** রাখা, একটা না।

```typescript
interface DesignOverride {
  className?: string          // পুরো section root এর জন্য
  imageClassName?: string     // শুধু image এর জন্য
  titleClassName?: string     // শুধু heading এর জন্য
  cardClassName?: string      // grid এর প্রতিটা card এর জন্য
  vars?: Record<string, string>  // CSS custom properties, যেমন {"--gap": "40px", "--card-bg": "#fff"}
}
```

JSON এ optional `design` field হিসেবে থাকবে:

```json
{
  "type": "feature-list",
  "heading": "Our Services",
  "design": {
    "className": "bg-navy-deep",
    "cardClassName": "border-2 border-gold",
    "vars": { "--icon-size": "48px" }
  },
  "cards": [
    { "title": "PRP Therapy", "icon": { "kind": "lucide", "value": "Sparkles" } }
  ]
}
```

## সমস্যা ২: common class + custom class একসাথে merge করলে conflict হয়

শুধু string concat (`base + " " + custom`) করলে Tailwind এ কাজ হবে না — কারণ `p-4` আর `p-8` দুটোই থেকে গেলে browser শেষেরটা নেয়, কিন্তু predictable না। এর জন্য **`tailwind-merge`** লাইব্রেরি লাগবে (তোমার এই প্রজেক্টেই `cn()` helper আছে `src/lib/utils.ts` তে — চেক করে দেখো ওটা `twMerge` ব্যবহার করছে কিনা)।

```typescript
// component এর ভেতরে:
<div className={cn(
  "grid gap-6 md:grid-cols-3",      // base/common design
  section.design?.className          // JSON থেকে override — conflict হলে এটা জিতবে
)}>
```

এতে করে common CSS by-default থাকবে, কিন্তু নির্দিষ্ট section এ override দিলে সেটা properly apply হবে, ভেঙে যাবে না।

## সমস্যা ৩: গভীর override (hover, pseudo-element, animation) — Tailwind class দিয়ে হয় না

এর জন্য **CSS variables** ব্যবহার করো। Component এর internal CSS/Tailwind arbitrary value var দিয়ে লেখা থাকবে, আর JSON থেকে সেই var এর ভ্যালু override করা যাবে:

```tsx
<div
  className="gap-[var(--gap,1.5rem)]"
  style={section.design?.vars}   // { "--gap": "3rem" } দিলেই override হয়ে যাবে
>
```

কোড না ছুঁয়ে শুধু JSON দিয়ে spacing/color/size বদলে ফেলা যাবে।

## সমস্যা ৪ (সবচেয়ে গুরুত্বপূর্ণ — তোমার workflow এর জন্য): admin থেকে JSON আসবে, common CSS দিয়ে render হবে, পরে manually তুমি target করে বদলাবে

এর জন্য root এ একটা **stable `data-` attribute** দাও, section এর `id` থেকে:

```tsx
<section data-section-id={section.id} className={cn(baseClasses, section.design?.className)}>
```

এখন তুমি একটা আলাদা override stylesheet (`overrides.css`) এ চাইলে manually লিখতে পারবে:

```css
[data-section-id="home-hero-2"] .card { background: #0a1f3d; }
[data-section-id="home-hero-2"] img { object-position: top; }
```

এটাই ঠিক তোমার বলা flow — **"admin json পাঠাবে, common css দিয়ে render হবে, পরে আমি manually modify করবো"** — কোনো component code না ছুঁয়ে, শুধু CSS override ফাইলে সেই section এর id targeted করে লিখলেই কাজ হবে। এটা component-level change লাগে না, শুধু JSON এ একটা consistent `id` থাকলেই হয় (যেটা তোমার `TreatmentBlockData` তে already অপশনাল ভাবে আছে — শুধু সব সেকশনে mandatory করে দিতে হবে)।

## সমস্যা ৫: icon/card/slider সব পেজে নেই

এখানে fix সহজ — component এ icon কে **সবসময় optional** ধরতে হবে, আর presence/absence দিয়ে conditionally render করতে হবে, আলাদা component বানানো লাগবে না:

```tsx
function Card({ item }: { item: CardData }) {
  return (
    <div className={cn("card-base", item.design?.cardClassName)}>
      {item.icon && <IconRenderer icon={item.icon} />}   {/* না থাকলে কিছুই render হবে না */}
      <h3>{item.title}</h3>
      {item.description && <p>{item.description}</p>}
    </div>
  )
}
```

`IconRenderer` একটাই থাকবে সব jaigar জন্য, `kind` দেখে switch করবে:

```tsx
function IconRenderer({ icon }: { icon: IconSpec }) {
  if (icon.kind === 'lucide') {
    const LucideIcon = LucideIcons[icon.value]
    return LucideIcon ? <LucideIcon /> : null
  }
  if (icon.kind === 'image') return <img src={icon.value} alt={icon.label ?? ''} />
  if (icon.kind === 'inline-svg') return <span dangerouslySetInnerHTML={{ __html: icon.value }} />
  if (icon.kind === 'font-class') return <i className={icon.value} />
  return null
}
```

| তোমার সমস্যা | সমাধান |
|---|---|
| section আর image একই CSS পাচ্ছে | element-wise আলাদা override slot (`imageClassName`, `cardClassName`...) |
| common + custom CSS conflict | `cn()` + `tailwind-merge` — override জিতবে, base ভাঙবে না |
| গভীর override দরকার | CSS variables (`vars`) JSON থেকে inline style এ পাস |
| admin json → পরে manual tweak | প্রতি section এ mandatory stable `id`, তার উপর ভিত্তি করে `data-section-id` + আলাদা override stylesheet |
| icon সব পেজে নেই | icon field সবসময় optional, component conditionally render করবে, একটাই shared `IconRenderer` |
